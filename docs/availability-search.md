# City availability and booking register

The guest route `#/availability` supports all 39 catalogue destinations and city, date, time, party filters. `/availability` reads current public SevenRooms widget availability for the 27 reviewed mappings. Only bookable provider slots on the requested date within ±90 minutes are returned. Provider failures and unsupported systems are distinct from an empty availability result. Reads have a ten-second provider timeout, bounded concurrency, in-flight deduplication and no completed-response or service-worker availability cache. Slots are not reservations; the provider rechecks them at checkout.

The wider reviewed registry has 62 mappings: 38 native forms and 24 official external links. The existing 22 Bokabord integrations remain separate. Neither original iframe loading nor a handoff proves a completed booking. Search coverage is smaller than booking-link coverage.

`api/booking-register.mjs` persists restaurant booking metadata in SQLite at `VELVET_BOOKINGS_DB` or alongside `VELVET_DATA` as `bookings.sqlite`. WAL and SHM files belong to the database; use SQLite's backup mechanism or stop/checkpoint the process before filesystem backup. Keep this directory private and backed up. The production API data mount persists it across container restarts.

Existing concierge and Bokabord results synchronize on writes and history reads. Guests can optionally save confirmation reference/date/time/party after receiving confirmation; the server always records these as `guest_reported`. The request cannot choose provider-confirmed status. No payment-card fields, arbitrary provider payloads or contact details are persisted by this register. Anonymous owners use the existing opaque HttpOnly cookie; history is owner-scoped, and existing authorized operators can view the register. No SevenRooms partner webhook/API has been enabled. Losing the guest cookie loses access to that guest's history; no cross-device recovery is implied.

Validation: backend validation/in-flight/error tests; SQLite restart, ownership, idempotency and metadata allowlist tests; browser mobile/stale-response tests; integrated local UI with read-only live Stockholm availability and a local-only guest report. No new reservations, holds or payments were submitted. Eight of thirteen prior simulated card journeys reached guest checkout; five still need further investigation, so payment/3DS completion is not claimed.
