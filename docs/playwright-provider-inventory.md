## Finding and counting boundary

The scanned production backend has one browser-booking implementation family: BokabordMirror, with a restricted submission path and explicit handoff limits. Its existence is not evidence of fully verified supplier checkout for every registered restaurant. No universal full-in-Velvet completion count can be established from this audit.

The JSON registry has **136 rows across 25 provider labels**, including **64 native_embed labels and 72 external_link labels**. The separate Bokabord registry has **22 rows**. The familiar sum 158 describes configuration entries, not 158 tested Playwright flows. Server initialization overlays Bokabord into availability configuration; it does not create a separate browser adapter per row. Registry labels are not evidence that a particular website currently renders or accepts a booking.

Only api/bokabord-mirror.mjs and api/providers/bokabord-availability.mjs launch Playwright in scanned production api modules. Browser scripts under scripts/ are probes/test harnesses, not automatically deployed provider adapters. Resolvers in api/providers/remaining-registry.mjs and next-wave-registry.mjs return destination metadata, not browser sessions.
